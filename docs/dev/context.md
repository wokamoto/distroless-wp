## Overview

Docker Compose stack for WordPress on **distroless** images (`gcr.io/distroless/static-debian13`).
Custom multi-stage images for `php` (PHP-FPM + WordPress core), `webserver` (nginx / httpd) and `wp-cli`,
built for two targets: `local` and `fargate` (AWS ECS Fargate; logs go to stdout/stderr). 🔵
This is an infrastructure/container repo: there is no application package manifest (no composer.json / package.json). 🔵

## Coding Conventions

### Dockerfiles 🟡
- Multi-stage: `builder` (custom distroless-builder image) → `gcr.io/distroless/static-debian13`.
- Every step has a one-line `#` comment above it.
- `RUN set -eux; \` with backslash continuation; the runtime filesystem is staged under `/opt`, then `COPY --from=builder /opt /`.
- Shared libraries are collected with `ldd` and copied in; no shell in the final image.
- Build args: `WP_VERSION`, `TIME_ZONE` (default `Asia/Tokyo`), `DEPLOY_ENV` (`local|fargate`).
- Fargate differences are applied with `sed -i` inside `if [ "${DEPLOY_ENV}" = "fargate" ]` (logs → `/dev/stdout`, `/dev/stderr`).

### Shell scripts 🟡
- POSIX `sh` (`#!/usr/bin/sh`), `set -eu`, settings via `${VAR:-default}` env overrides, retry loops with a max attempt count.

### PHP (in-house code: mu-plugins, wp-config) 🟡
| Target | Convention | Example |
|--------|-----------|---------|
| Functions | snake_case with `__` prefix (global namespace) | `__url_normalize_includes_asset` |
| Variables | snake_case | `$home_url`, `$is_production_stage` |
| Constants | UPPER_SNAKE via `define()` | `WP_CONTENT_DIR` |
| Files | snake_case | `url_normalize.php` |

- Guard: `if (!defined('ABSPATH')) { exit; }`; hooks registered inside an `add_action('init', ...)` closure.
- PHPDoc on functions (`@param`, `@return`).
- Configuration comes from env vars: `getenv('X') ?: 'default'` (`DB_*`, salts, `STAGE`).
- `STAGE` drives `WP_DEBUG`, `WP_DEBUG_LOG`, `WP_ENVIRONMENT_TYPE` (debug display is always off).

### Logging 🔵
- local: files under `/var/log/{nginx,httpd,php-fpm,mysql}` mounted to `./logs/*`.
- fargate: stdout/stderr.

### Commits 🔵
- Conventional Commits with a scope, e.g. `fix(webserver): ...`, `build(docker): ...`, `docs(readme): ...`.

## Additional Notes

- Distroless runtime images have no shell: `docker compose exec <svc> sh` fails. Call binaries by absolute path (`/usr/local/bin/php`, `/usr/sbin/nginx`). 🟡
- Content is mounted read-only into `webserver` and read-write into `php` / `wp-cli`. 🔵
- PHP execution is denied under `/assets/{languages,themes,uploads,upgrade}` and `/wp/wp-includes`; `xmlrpc.php` and `wp-config.php` return 404. 🔵
- Changes under `config/` and `bin/` must be kept in sync between the **nginx** and **httpd** variants, and across **php83/84/85** Dockerfiles. 🟡
- ⚠ `.env` is tracked in git. Do not put real secrets in it; it is read-denied for agents in this environment. 🔵
- ⚠ The README says content lives at `/var/www/html/content`, but the code uses `/var/www/html/assets` (commit e778523). The README needs updating. 🟡
- `www/content/plugins/fluent-smtp` is third-party code with local, uncommitted modifications. Avoid changing it unless asked. 🔵
- Docs: `README.md` (English) and `README_ja.md` (Japanese, です/ます style) are kept in parallel. 🔵
